# ORBIT — پورتفولیوی سه‌بعدی علیرضا مشایخی

> «دنیای دیجیتال من را کشف کن» — یک گوی فضایی تعاملی که هر مانیتور روی آن
> دروازهٔ ورود سینمایی به یک بخش واقعی از پورتفولیو است.

## اجرا

```bash
pnpm install
pnpm --filter @aboutMe/web build     # یا dev برای توسعه
pnpm --filter @aboutMe/web start     # http://localhost:3333
```

> نکته: پکیج `@aboutMe/contracts` برای تایپ‌چک وب باید یک بار بیلد شده باشد
> (`pnpm --filter @aboutMe/contracts build`) — توربو در `pnpm build` ریشه این را خودش مدیریت می‌کند.

## ویرایش محتوا (مهم)

**همهٔ محتوا یک جا است: `apps/web/src/data/portfolio.ts`**

- نام، عنوان، بیو و شعار — `profile`
- **اطلاعات تماس** — `contact`: فیلدهای خالی در UI نمایش داده نمی‌شوند.
  ایمیل/لینکدین/تلگرام/تلفن را آنجا بگذار تا کانال مربوط فعال شود.
  (گیت‌هاب از روی همین مخزن عمومی قابل تأیید بود و درج شده است.)
- مهارت‌ها، حوزه‌های تخصصی، مراحل روش کار — آرایه‌های همان فایل
- **پروژه‌ها** — `projects`: برای هر پروژه فقط اطلاعاتی درج شده که از خودِ
  وب‌سایت عمومی‌اش قابل مشاهده بوده است. فیلدهای `roleFa`, `year`, `tech`,
  `problemFa`, `decisionsFa` را با اطلاعات واقعی خودت کامل کن؛
  مقدار `null`/خالی در UI صادقانه به‌صورت «در حال تکمیل» مدیریت می‌شود و
  هیچ آمار یا قابلیتی جعل نشده است.
  دو سایت `penguin.market` و `zarvantrip.com` هنگام بررسی در دسترس نبودند؛
  برای آن‌ها هیچ مشخصاتی حدس زده نشده است.
- کاور پروژه‌ها رویه‌ای (SVG قطعی از روی slug) ساخته می‌شود تا اسکرین‌شات جعلی
  نمایش داده نشود؛ هر وقت تصویر واقعی آماده بود، `ProjectCover` را جایگزین کن.

## معماری

```
apps/web/src/
├─ data/portfolio.ts            ← تنها منبع محتوا
├─ features/orbit/
│  ├─ store.ts                  ← ماشین حالت (zustand) + وضعیت گذرا + حفظ زاویه
│  ├─ Scene.tsx                 ← صحنه: کره، مانیتورها، کنترل چرخش، ریگ دوربین
│  ├─ screen-textures.ts        ← محتوای زندهٔ مانیتورها (CanvasTexture)
│  ├─ OrbitCanvas.tsx           ← بوم وب‌جی‌ال (dynamic import، بدون SSR)
│  └─ OrbitExperience.tsx       ← اسکرول→زوم، HUD، حجاب ورود، جایگزین بدون WebGL
├─ components/portfolio/        ← پوستهٔ صفحات داخلی، کاور پروژه، نشان ORBIT
└─ app/
   ├─ page.tsx                  ← تجربهٔ ORBIT (+ محتوای DOM برای سئو/دسترس‌پذیری)
   ├─ about|skills|work|approach|expertise|contact
   ├─ work/[slug]               ← جزئیات پروژه (SSG، dynamicParams=false)
   └─ (panel)/users             ← نمونهٔ قالب پایه، دست‌نخورده
```

### ماشین حالت

`INTRO → APPROACH → INTERACTIVE → ENTERING → (route بخش) → RETURNING → INTERACTIVE`

- فقط **یک** سیستم دوربین را کنترل می‌کند (`CameraRig`) و فقط یک کنترلر چرخش (`useSphereControls`).
- ورود به مانیتور: کواترنیون گروه با slerp به معکوس چارچوب محلی مانیتور می‌رسد
  (مانیتور روبه‌روی دوربین، بدون رول)، بعد دوربین به داخل صفحه شیرجه می‌زند و روت عوض می‌شود.
- زاویهٔ پیش از ورود در `sessionStorage` ذخیره می‌شود؛ بازگشت (`/?return=1`، دکمهٔ Back
  یا Escape) دوربین را از نزدیک عقب می‌کشد و همان زاویه را برمی‌گرداند.
- انتخاب مانیتور با **برخورد واقعی** اشاره‌گر به مش مانیتور است (R3F raycast)؛
  هاور فهرست DOM مسیر جدا دارد و نمی‌تواند کلیک روی فضای خالی را به ورود تبدیل کند.
- تمایز کلیک/درگ فقط با مقدار حرکت است (نه زمان) — روی دستگاه کند زمان تحویل رویداد قابل اعتماد نیست.

### عملکرد و دسترس‌پذیری

- three.js فقط در چانک تنبل صفحهٔ اصلی است (در HTML اولیهٔ هیچ روتی نیست).
- DPR و سایه‌ها روی دستگاه ضعیف محدود می‌شوند؛ بافت‌ها dispose می‌شوند.
- `prefers-reduced-motion`: بدون اسکرول‌-زوم و چرخش خودکار، مستقیم تعاملی.
- بدون WebGL: نسخهٔ متنی کامل با همان ناوبری. متن‌های حیاتی همیشه در DOM هستند.
- کیبورد: کلیدهای جهت‌دار روی کانواس، دکمه‌های واقعی فهرست بخش‌ها، Escape برای بازگشت/لغو.

## گزارش سه دور ارزیابی و اصلاح

### دور اول — صحت منطق و رفتار

یافته‌ها و اصلاحات (همه واقعاً اصلاح و دوباره تست شدند):

1. **تپ سریع موبایل مانیتور را انتخاب نمی‌کرد** — فقط `pointermove` هندل می‌شد؛
   `onPointerDown` به مش مانیتورها اضافه شد.
2. **هاور کهنهٔ DOM** می‌توانست کلیک روی فضای خالی کانواس را به ورود تبدیل کند —
   پرچم `hoverFromDom` اضافه شد؛ ورود از کانواس فقط با برخورد واقعی.
3. **دوربین در بازگشت از دوردست شروع می‌کرد** — نقطهٔ شروع ریگ بر اساس فاز آغازین تنظیم شد.
4. **Escape در فرم تماس** کاربر در حال تایپ را از صفحه بیرون می‌برد — در فیلدهای فرم فقط blur می‌شود.
5. **Soft-404**: اسلاگ ناموجود پروژه ۲۰۰ برمی‌گرداند — `dynamicParams=false`؛ حالا ۴۰۴ واقعی.
6. ذخیرهٔ زاویهٔ بازگشت بعد از لغو ورود با Escape می‌توانست وضعیت نیمه‌کاره را ذخیره کند —
   قفل `restoreQuat` تا چرخش واقعی بعدی کاربر حفظ می‌شود.
7. R3F روی کانواس `touch-action:none` می‌گذاشت و اسکرول لمسی فاز نزدیک‌شدن را می‌شکست —
   همگام‌سازی صریح بر اساس فاز.
8. تایپ `as const` روی اطلاعات تماس، فیلد خالی را `never` می‌کرد — تایپ صریح `string`.

### دور دوم — کیفیت بصری و UX (با اسکرین‌شات مرورگر واقعی)

1. **لبهٔ مربعی هالهٔ مانیتورها دیده می‌شد** — صفحهٔ تخت با بافت شعاعی جایگزین شد.
2. کره شبیه «هولوگرام وایرفریم» بود — یک لایهٔ وایرفریم حذف و دیگری کم‌رنگ شد؛
   متریال به فلز تیرهٔ براق با انعکاس محیطی قوی‌تر رسید.
3. قطعات شناور مثلث‌های مشکیِ شبیه آرتیفکت بودند — روشن‌تر، کوچک‌تر و کمتر شدند.
4. لکهٔ سبز نور زیرین روی بدنه — شدت/موقعیت اصلاح؛ برق روبه‌رو برای خوانایی حجم اضافه و بعد متعادل شد.
5. نمای دور به‌اندازه کافی دور نبود — فاصلهٔ آغازین ۱۱٫۸ ← ۱۳٫۴.
6. **ناهم‌گامی حجاب CSS با انیمیشن سه‌بعدی روی FPS پایین** — زمان‌بندی ورود/بازگشت
   به ساعت واقعی (timestamp) منتقل شد.
7. گلیف ◎ در برخی محیط‌ها رندر نمی‌شد — نشان ORBIT با CSS بازسازی شد.

### دور سوم — باگ، عملکرد و شرایط مرزی

1. **معیار زمانی کلیک (۹۰۰ms) تپ درست را روی رندر کند رد می‌کرد** — در شنود رویدادها
   فاصلهٔ تحویل down/up به ۴–۶ ثانیه می‌رسید؛ معیار زمان حذف و فقط حرکت ملاک شد،
   سپس تپ لمسی در تست خودکار پاس شد.
2. `robots.txt` کل سایت را Disallow کرده بود — اصلاح شد (فقط `/users` بسته است).
3. صفحات 404/خطا/لودینگ با تم روشن قالب در بدنهٔ تاریک ناهماهنگ بودند — بازطراحی ORBIT.
4. تخصیص شیء در حلقهٔ فریمِ کنترل چرخش حذف شد (بردار/کواترنیون موقتِ از پیش ساخته‌شده).
5. نشانگر جهانی (`cursor:pointer`) هنگام خروج از صحنه پس داده می‌شود.
6. بررسی نشت: همهٔ CanvasTextureها و بافت‌های اشتراکی هنگام unmount آزاد می‌شوند.

### نتایج تست‌های اجراشده

- `typecheck` ✅ · `lint` ✅ · `build` ✅ (همهٔ روت‌ها استاتیک/SSG)
- تست خودکار مرورگر (Chromium هدلس + SwiftShader، با Playwright):
  - دسکتاپ: لود و رندر WebGL، اسکرول→تعاملی و قفل اسکرول، درگ و اینرسی،
    **کلیک روی سطح واقعی مانیتور → ورود سینمایی → /about**، ورود با دکمهٔ DOM و گارد دابل‌کلیک،
    بازگشت با Escape و حفظ زاویه، فیلتر گالری (۸←۱)، Back/Forward، صفر خطای کنسول — **۸/۸ پاس**
  - موبایل (iPhone 13): رسیدن به تعاملی، درگ لمسی بدون ناوبری ناخواسته، **تپ روی مانیتور → ورود** — پاس
  - `prefers-reduced-motion`: مستقیم تعاملی — پاس · بدون WebGL: جایگزین متنی — پاس

### محدودیت‌های صادقانه

- تست مرورگر با رندر نرم‌افزاری (SwiftShader) انجام شد؛ نرخ فریم و زمان‌بندی آن
  نمایندهٔ سخت‌افزار واقعی نیست — نرمی نهایی انیمیشن‌ها روی دستگاه واقعی بهتر است
  و روی GPU واقعی باید یک بار چشمی تأیید شود.
- Safari/iOS واقعی در محیط تست در دسترس نبود.
- اطلاعات پروژه‌های `penguin.market` و `zarvantrip.com` و نقش/فناوری دقیق همهٔ
  پروژه‌ها باید توسط صاحب پورتفولیو در `data/portfolio.ts` تکمیل شود.
